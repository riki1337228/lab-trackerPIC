# Git-процес проєкту Lab Tracker

## Модель гілкування

Спрощена trunk-based модель (близька до GitHub Flow):

- `main` — стабільна гілка; містить лише затверджені артефакти.
- Кожна зміна виконується в короткоживучій гілці від `main`
  і повертається через `git merge --no-ff` (щоб злиття було видно в історії).
- Іменування гілок: `<тип>/<короткий-опис>`, де тип збігається з префіксом
  коміту (`spec/`, `feat/`, `docs/`, `test/`). Для розмежування авторства
  під час експериментів використовуються префікси `agent/` (зміни агента)
  та `human/` (ручні зміни людини).

## Конвенція повідомлень комітів

Формат: `<префікс>: <що зроблено>` (українською, в наказовому способі).

| Префікс | Артефакт / дія SDD |
|---|---|
| `spec:` | Зміна специфікації або опису задуму (`/spec`) |
| `test:` | Тести та критерії приймання (`/tests`) |
| `feat:` | Програмний код, нова функціональність (`/src`) |
| `fix:` | Виправлення коду, що не відповідає специфікації |
| `docs:` | Документація процесу та проєкту (`/docs`, README) |
| `log:` | Журнали взаємодії з агентом та рішень (`/logs`) |
| `gate:` | Рішення контрольної точки (GIT-GATE тощо) |
| `chore:` | Службові зміни (структура, конфігурація Git) |
| `merge:` | Коміт злиття, зокрема з вирішенням конфлікту |

Один коміт — один тип артефакту. Якщо зміна зачіпає кілька типів, її
розбивають на кілька комітів.

## Позначення авторства

- Коміт, вміст якого згенеровано кодинговим агентом, містить мітку `[agent]`
  у заголовку та трейлер `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Ручна зміна людини позначається міткою `[human]` у заголовку.
- Авторство **не є** аргументом при вирішенні конфліктів: еталоном є
  затверджений артефакт у `/spec`.

## Правило вирішення конфліктів

1. Визначити, якої вимоги стосується конфліктний фрагмент.
2. Знайти цю вимогу в `/spec`. Обрати варіант, що їй відповідає.
3. Якщо вимоги немає або вона неоднозначна — не вигадувати її в коді,
   а зафіксувати відкрите питання в `/spec` для наступного циклу специфікації.
4. Записати обґрунтування в `/logs`.
